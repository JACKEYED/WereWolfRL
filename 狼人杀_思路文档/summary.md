2. “斯坦福小镇”在你的项目里怎么用？

斯坦福小镇本质上是一个 Generative Agents 社会模拟环境。它的关键不是地图，而是：

Agent 有身份
Agent 有记忆
Agent 有日程
Agent 会观察环境
Agent 会和别人对话
Agent 会形成计划
Agent 会根据经历更新行为

你可以把狼人杀放进一个“村庄场景”里，而不是传统命令行游戏。

比如：

白天：
所有玩家在村庄广场集合，依次发言、质疑、辩论、投票。

夜晚：
狼人进入狼人房间商量击杀目标；
预言家在神职房间查验玩家；
女巫在自己的房间决定救人或毒人；
猎人等待死亡触发技能。

平时：
玩家可以在不同地点产生非正式对话，比如酒馆、广场、房间门口。
这些对话也可以成为后续推理依据。

这样你的游戏就不是简单的：

第 1 号发言
第 2 号发言
第 3 号发言
投票

而是变成：

Agent 在真实场景中移动、观察、交流、形成记忆，然后进入狼人杀决策。

这会更像一个“真实社交狼人杀环境”。


1. 每个 AI 玩家应该是什么结构？

建议每个 Agent 都不要直接写成：

prompt → LLM → 发言

而应该拆成：

观察模块 Observation
→ 记忆模块 Memory
→ 推理模块 Reasoning
→ 策略模块 Policy
→ 发言模块 Speech
→ 动作模块 Action

一个 Agent 的内部结构可以是：
（可以写成tool，skill方式）
Agent_i
├── public_memory      # 所有人都知道的信息
├── private_memory     # 自己观察到的信息
├── hidden_role        # 自己真实身份，只有自己知道
├── belief_state       # 对其他玩家身份的判断
├── strategy_state     # 当前策略，如伪装、跟票、冲票、站边
├── speech_generator   # 生成自然语言发言
└── action_selector    # 选择投票、查验、刀人、救人、毒人等动作

对本地 Qwen7B Agent，需要额外加一个 训练数据记录器，记录它每一轮的输入、输出、结果和奖励。


5. 关键点：训练的不是“会说话”，而是“会赢”

你的目标是让本地 Qwen7B 逐渐超过其他 API 模型。这里不能只训练它生成更自然的发言，而要训练它的 策略能力。

策略能力包括：

```text
1. 身份推理能力
   谁像狼人，谁像预言家，谁像女巫。

2. 阵营判断能力
   哪些人可能是一伙，哪些人互踩，哪些人互保。

3. 语言伪装能力
   狼人如何伪装成好人，神职如何隐藏或跳出身份。

4. 投票决策能力
   什么时候跟票，什么时候分票，什么时候冲票。

5. 长期规划能力
   不是只看当前轮，而是考虑后面几轮怎么赢。

6. 对手建模能力
   哪些 API Agent 容易相信什么话，哪些 Agent 容易被带票。
```

所以你的训练数据要围绕这些能力设计。
